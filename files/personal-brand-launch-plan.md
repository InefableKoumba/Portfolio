# Personal Brand Launch Plan — Master Checklist

Work through this top to bottom. Nothing below it should be started until the section above is locked, since each layer depends on the one before it (positioning → identity → platforms → templates → content engine → launch → sustain).

---

## Phase 1 — Positioning (foundation, do not skip)

- [ ] Core narrative written and finalized (the "I'm a software engineer who applies real engineering rigor..." statement)
- [ ] 3 content pillars named and defined: **Constraint Engineering**, **Math-to-Code**, **Build Log**
- [ ] One-sentence tagline finalized, word-for-word, e.g. *"Engineering for the world's hardest constraints."*
- [ ] Target audience written down explicitly (e.g. "mid-to-senior African developers, technical founders, CS students wanting real depth") — this shapes tone and vocabulary choices later
- [ ] List of 15–20 real stories/decisions from your games, APIs, and websites you can turn into posts (your content backlog — do this now while it's fresh)

## Phase 2 — Visual identity

- [ ] Profile photo chosen — one photo, same across all platforms, good lighting, professional but approachable
- [ ] Color palette locked (see design system below) and saved somewhere you'll actually reuse it (Notion, Figma, or just this doc)
- [ ] Fonts locked (display + body + caption/data)
- [ ] Signature visual element defined (your "signal trace," a consistent chart style, whatever recurring mark you'll use)
- [ ] Post templates built for each content type (delivered below — Constraint Files, Math in the Wild, Build Log)
- [ ] Cover photos for LinkedIn/Facebook designed using the same palette and tagline

## Phase 3 — Platform setup

- [ ] **LinkedIn:** headline rewritten with tagline + pillars, About section tells the full narrative, featured section pinned with your best 1–2 pieces (or a placeholder until you have one)
- [ ] **Facebook:** page or profile bio matches LinkedIn positioning, same photo/cover, page category set correctly if using a Page
- [ ] **WhatsApp:** display name and status format decided (e.g. always start status text with a consistent short tag like "⚙️ Build note:")
- [ ] Handle/username consistency checked across all 3 platforms — same or as close as possible
- [ ] Link-in-bio or simple landing page decided (even a one-page site listing your projects) — optional but strengthens credibility, can wait until Phase 6

## Phase 4 — Content engine (how you'll actually sustain this)

- [ ] Weekly rhythm confirmed:
  - Mon (LinkedIn): Constraint Engineering deep post
  - Wed (LinkedIn/FB): Math-to-Code teaching post
  - Fri (LinkedIn): Build Log / problem breakdown
  - Daily (WhatsApp + FB): quick tips, behind-the-scenes
  - Monthly: one flagship deep-dive
- [ ] Content selection checklist (already built) kept somewhere you'll check it before every post
- [ ] First 4 weeks of topics drafted in advance (buffer so you're never starting from zero the morning of)
- [ ] Simple content capture habit set up — e.g. a running notes file/app where you jot down post ideas the moment they occur during real work, not just when you sit down to "create content"
- [ ] Batching plan decided — e.g. write/design 2–3 posts in one sitting per week rather than daily from scratch

## Phase 5 — Pre-launch quality check

- [ ] 3–5 posts fully drafted and checklist-approved before your first public post (never launch with zero buffer)
- [ ] Ask 2–3 trusted peers to review your positioning statement and one draft post for clarity and tone
- [ ] Test how your templates actually look on mobile (most viewers will see them on a phone screen — check legibility, not just desktop preview)
- [ ] Decide your engagement policy: how often you'll reply to comments, whether you'll DM new followers, how you'll handle disagreement or criticism publicly

## Phase 6 — Launch

- [ ] Announcement post written — tell people what you're going to be posting about and why, so early followers know what to expect (sets the frame for eversyone who finds you after)
- [ ] Personally share the announcement with your existing network (don't rely on the algorithm for post #1)
- [ ] First week's content scheduled or ready to go live daily without last-minute scrambling

## Phase 7 — Sustain and iterate

- [ ] Weekly 15-minute review: which post pillar performed best, which felt easiest/hardest to make
- [ ] Monthly check: is your content still passing the checklist, or has quality crept downward under time pressure?
- [ ] Quarterly check: does your positioning still fit, or has your work evolved enough to justify a pillar adjustment?
- [ ] Community habit: reply to every genuine comment for at least the first 3 months — this is what turns an audience into a community

## Design system reference (for every template you build)

| Element | Value |
|---|---|
| Background | `#0E1A2B` (deep blueprint navy) |
| Panel/card background | `#16263D` |
| Signal accent (structure, dividers, labels) | `#FFB238` (amber) |
| Data accent (numbers, math, highlights only) | `#5EEAD4` (cyan) |
| Primary text | `#F5F3EC` (warm off-white) |
| Muted text | `#9FB0C3` |
| Display font (headlines) | JetBrains Mono, bold |
| Body font | IBM Plex Sans |
| Caption/data/label font | IBM Plex Mono, uppercase, letter-spaced |
| Signature element | "Signal trace" — thin jagged waveform line under every series eyebrow label |

Reuse this table every time you or a collaborator builds a new graphic — nothing outside this palette/type system unless you deliberately revise it.
